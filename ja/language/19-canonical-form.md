# 正準形

プログラムの**正準形**は、フォーマッタ（`cernith fmt`）の出力です。プログラムの構文木とコメントだけから決まる関数で、空白、改行、宣言の順序、括弧のつけ方まで、書き方が一つに定まります。

文法は書式に依存しません（[02 字句](02-lexical-structure.md)）。どんな書式で書いても、文法上は読めます。正準形でないテキストには、診断が出ます。

- `cernith check` では、警告 `W0102`（non-canonical-text）です。正準形のテキストが添えられ、「ファイルを正準形で置き換える」という安全な修正が提案されます。ほかの診断を隠さず、遅らせないための扱いです。
- リリースビルドでは、ソースのテキストが正準形と一致しなければ、エラー `E0101`（non-canonical-form）です。

ソースを書き出す処理系のコマンド（`cernith fmt`、編集コマンド、修正の適用）は、すべて正準形で書きます。

フォーマッタには、次の性質があります。

- **冪等**：正準形を整形しても変わりません。
- **意味を保つ**：整形の結果を読み直すと、同じ構文木になります（宣言の並び順を除きます。並び順は正準形の一部です）。
- コメントの文字列は変えません。

順序に意味があるものは、整形では並べ替えません：レコードのフィールド、バリアントのケース、関数のパラメータ、同じ種類の節（論理積ですが、書いた順のまま）、呼び出しの引数（ラベルは宣言の順でなければなりません）、文。

## 規則

### テキスト

1. BOM なしの UTF-8、改行は LF、タブなし、行末の空白なし。ファイルの終わりは改行 1 つだけ。先頭と末尾に空行を置かない。
2. インデントは 1 段 2 スペース。波括弧を開くと 1 段深くなり、折り返した括弧のグループや演算子の連なりの続きの行は、1 段深くなる。
3. コードの行は 80 桁まで（Unicode スカラー値で数える）。コメントの行と、折り返す場所のない行（長い文字列リテラル 1 つなど）は除く。

### ファイルの構成

4. `module` 行より前のコメントは、先頭に置き、`module` との間に空行を入れない。
5. 順序は、`module` 行、空行、`import`（パス、別名の順に整列、間に空行なし）、空行、定義。`import` のないファイルは、`module` の後に空行 1 つ。
6. 定義は 3 つのグループで、この順に並びます。定義と定義の間は、空行 1 つです。
   1. **型**：`type`、`record`、`variant`、`resource`、`capability`、`manifest`。種類にかかわらず、名前順。
   2. **定数**。名前順。
   3. **関数**：通常の `fn`、`spec fn`、foreign 関数のすべて。名前順。各関数の直後に、その関数の `example`（名前順）、次に `property`（名前順）を置く。

   名前の比較は、コードポイント順（ASCII）です。
7. `foreign` の行は、対応する `fn` の直前に、バックエンドの名前の順に置く。

### ブロックと文

8. `{` は行末に置く。空でないブロックは、要素を 1 行に 1 つ、1 段深く書き、`}` を単独の行に置く（`} else {` と `} else if 条件 {` を除く）。空のブロックは `{}`。
9. ブロックは節で始まる（関数：`requires`、`ensures`、`decreases`。ループ：`invariant`、`decreases`。property：`requires`）。節は `;` で終わる。節とほかの内容の間には空行を 1 つだけ置き、ブロックの中にほかの空行は置かない。
10. `let`、`var`、代入、`return`、`discard`、`assert`、呼び出しの文は `;` で終わる。`if`、`match`、`for`、`while` は `;` を付けない。ブロックの最後の式にも付けない。`if`、`match`、`for`、`while` は常に複数行の形で書く。
11. `match` のケースは 1 行に 1 つで、末尾にカンマを付ける。ブロックのケースも `},` で終わる。

### 式

12. `,` と `:` の後、二項演算子、`=`、`=>`、`->` の前後には、スペースを 1 つ置く。括弧の内側、`,` `:` `;` の前、`.` `..` `..=` `::` の周り、単項 `-` の後には置かない。`not` の後には 1 つ置く。型引数に内側のスペースはない（`List<Int>`）。
13. **括弧**は、必要なときだけ付ける：優先順位や結合性が要求する場合と、`or` のオペランドの `and` 式。不要な括弧は消し、同じ優先順位の右のオペランドには括弧を付ける（`a - (b - c)`）。左結合の連なりの左の括弧は、連なりに合流させる（`(a + b) + c` は `a + b + c`）。
14. **折り返し**は、外側のグループから順に決める。`( )` と `[ ]` の中のカンマ区切りの要素、同じ優先順位の演算子の連なりが、グループになる。
    - グループの先頭から、外側が折り返せる次の位置までが 80 桁に収まり、途中に必ず改行になるもの（複数行のブロック）がなければ、**1 行**で書く。
    - そうでなければ**折り返す**。括弧のグループは、各要素を 1 段深く 1 行ずつ書き、最後の要素の後にカンマを付け、閉じ括弧を単独の行に置く。演算子の連なりは、各演算子の前で折り返し、続きの行は演算子で始め、1 段深くする。
    - 内側のグループは、外側が決まったあと、独立に決める。
    - 1 行に書くグループには末尾のカンマを付けない。末尾のカンマを付けるのは、呼び出しの引数、リストリテラル、パラメータ一覧、パターンのフィールド、バリアントのケースのフィールドのグループだけ。
15. 関数のヘッダは、`{` まで含めて収まれば 1 行で書く。収まらなければ、パラメータ一覧を折り返し、`) -> 型 uses 効果 {` は閉じ括弧の行に置く。`uses` の効果は、重複なく 1 回ずつ、辞書順（小文字の効果名、その後に効果パラメータ）に並べる。

### リテラル

16. 整数は 10 進数。真偽値は `true`、`false`。
17. 浮動小数点数は、同じ値を読み戻せる最短の 10 進桁列。10 進の指数が -6 から 20 のときは位取り記法（`123.45`、`0.000001`。小数点の後に 1 桁以上）、それ以外は `d.ddde指数` の科学記法（`1.0e21`、`1.0e-7`。指数の符号は負のときだけ）。
18. 文字列は、中身を読み取って、最小限のエスケープで書き直す：`\\`、`\"`、`\n`、`\t`、`\r`、および一般カテゴリが Cc、Cf、Co、Zl、Zp の文字（Unicode 18.0.0 の固定の表による）の `\u{16 進数}`（小文字、0 埋めなし）。それ以外の文字は、そのまま書く。

### コメント

19. コメントは `//` の行コメント。`//` の後の文字は、後続のスペースも含めてそのまま。コードの後ろのコメントは、続く要素の前の行に移る。
20. コメントは、続く要素（定義、`import`、文、節、フィールド、ケース、`match` のケース）に属し、そのインデントで一緒に動く。閉じ括弧の前のコメントはブロックの終わりに、最後の定義の後のコメントはファイルの終わりに残る。ほかの位置のコメント（式やパラメータ一覧の途中）はエラー。コメントに意味はない。

## 例

次のプログラムは、文法上は正しい（`W0102` の警告だけが出る）が、正準形ではありません。

```cernith-error W0102
module guide.messy;
import std.list;
pub fn zeta(x:Int)->Int{x+1}
pub const limit:Int=3;
example z for zeta{zeta(x:1)==2}
pub type B=distinct Int;
pub fn alpha(items:List<Int>,count:Int,other_long_parameter_name:Int,more:Int)->List<Int>{
  requires count>=0 and count<=items.length;
  ensures result.length==count;
  list.take(items:items,count:count)
}
pub record A{x:Int,y:Int,}
```

正準形は次のとおりです。`import` の後ろと定義の間に空行が入り、型、定数、関数の順に並び、関数は名前順（`alpha`、`zeta`）で、`zeta` の直後に `example` が置かれます。長いヘッダは、パラメータを 1 行ずつ折り返されます。

```cernith
module guide.messy;

import std.list;

pub record A {
  x: Int,
  y: Int,
}

pub type B = distinct Int;

pub const limit: Int = 3;

pub fn alpha(
  items: List<Int>,
  count: Int,
  other_long_parameter_name: Int,
  more: Int,
) -> List<Int> {
  requires count >= 0 and count <= items.length;
  ensures result.length == count;

  list.take(items: items, count: count)
}

pub fn zeta(x: Int) -> Int {
  x + 1
}

example z for zeta {
  zeta(x: 1) == 2
}
```

## 限界

- 長い比較式を折り返すと、見た目が読みにくくなることがあります。正準形が目指すのは、見た目の美しさではなく、決定性です。
- 同じ種類の節は、書いた順のまま残るので、`requires` の順序だけが違う 2 つのプログラムは、意味は同じでも、正準形のテキストは異なります。
- 識別子の綴り（snake_case、PascalCase）は、フォーマッタではなく、字句解析器が強制します。
